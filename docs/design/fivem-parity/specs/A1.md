# Spec A1: Lua vector helpers

Scope: Lua only (client and server), `crates/sixm-lua`. No JS change (JS vectors
already have `.dot/.cross/.normalize`). No `sixm-core` change.

## Names (verified)

`sources/scripting-reference.md:106,112` lists, for Lua client and server:
`cross, dot, inv, norm, quat, slerp, vector, vector2, vector3, vector4`.
Already present (`vector.rs:202-215`): `vector2/3/4`, `vec2/3/4`, `quat`.
To add: `vector`, `dot`, `cross`, `norm`, `inv`, `slerp`.
**Dropped:** `normalize` (not in the catalogue). `native-coverage.tsv` has no
entries for these (they are not natives). The catalogue gives names only, so
the behavior below is the simplest consistent one.

## Files

Only `crates/sixm-lua/src/vector.rs` (code), `crates/sixm-lua/tests/vectors.rs`,
docs and types. They are installed by the existing `vector::install`
(`natives.rs:67`), which runs on both sides, so nothing else is wired.

## Code (`vector.rs`)

1. Refactor `construct` (line 255): move the flatten loop (the `push` closure
   and the `for arg in &args` loop, lines 267-285) into
   `fn flatten(name: &str, args: &[LuaValue]) -> mlua::Result<([f32; MAX_LEN], usize)>`
   returning the components (extra ones beyond 4 are not stored) and the
   count. Error text unchanged:
   `"{name}: expected numbers or vectors, got {type}"`. `construct` keeps its
   single-number shortcut and calls `flatten`; existing tests must still pass.
2. In `install`, after the `quat` registration, add six
   `globals.raw_set(name, lua.create_function(...))` calls:

| Global | Signature | Result | Errors (exact prefix, then `got ...`) |
|---|---|---|---|
| `vector(...)` | numbers/vectors, flattened | vector2/3/4 by total count (a single number is count 1, so an error) | `vector: expected numbers or vectors, got <lua type>`; count not 2..=4: `vector: expected 2 to 4 components, got <n>` |
| `dot(a, b)` | two vectors of equal size | Lua number: sum of products, in f64 like `Vector::length` | `dot: expected two vectors of the same size, got <describe a> and <describe b>` |
| `cross(a, b)` | two `vector3` | `vector3` | `cross: expected two vector3, got <describe a> and <describe b>` |
| `norm(v)` | vector or quat | same type, divided by its length; length 0 returns an unchanged copy (no NaN) | `norm: expected a vector or quat, got <describe v>` |
| `inv(q)` | quat | conjugate divided by squared length (`[w,-x,-y,-z]/len^2`); zero quat is an error | `inv: expected a quat, got <describe q>`; zero: `inv: quat has zero length` |
| `slerp(a, b, t)` | quat, quat, number | quat | `slerp: expected (quat, quat, number), got <describe a>, <describe b> and <describe t>` |

   `slerp` algorithm (inputs are not normalized by the function, f64 math,
   then `float_to_f32`, line 373): `d = a.b`; if `d < 0` use `-b` and `d = -d`;
   if `d > 0.9995` result is `normalize(a + t*(b-a))`; else
   `theta = acos(d)`, `result = (sin((1-t)theta) a + sin(t theta) b) / sin(theta)`.
   `t` is not clamped. Use `number_of` (line 351) to read `t`.
3. Reading helpers to reuse: `read` (343) for vectors, `read_quat` (518) for
   quats, `describe` (335) for error text. Extend `describe` so a quat prints
   `quat` (add `else if read_quat(value).is_some() { "quat" }`; today it falls
   to `type_name()` = `userdata`). Add small methods: `Vector::dot(&self, &Self) -> f64`,
   `Vector::cross3(&self, &Self) -> Self` (len 3 only, caller checks),
   `Vector::normalized(&self) -> Self`, `Quat::dot`, `Quat::normalized`,
   `Quat::inverse`. All `Copy` math, no heap allocation. No `unsafe`, no `as`
   casts beyond the existing `float_to_f32`/`f64::from` pattern.

## Tests (`crates/sixm-lua/tests/vectors.rs`, helpers `run` / `lines`)

- `vector_picks_its_size_from_the_argument_count`: `type(vector(1,2))`,
  `type(vector(1,2,3))`, `type(vector(vector2(1,2), 3, 4))` give
  `vector2, vector3, vector4`; `pcall(vector, 1)` -> `vector: expected 2 to 4 components, got 1`;
  `pcall(vector, 1,2,3,4,5)` -> `... got 5`; `pcall(vector, 'a')` ->
  `vector: expected numbers or vectors, got string`.
- `dot_multiplies_components_and_needs_equal_sizes`: `dot(vector3(1,2,3), vector3(4,5,6)) == 32.0`
  (`Value::Float(32.0)`); `dot(vec2(1,0), vec2(0,1)) == 0`; mixed sizes and
  `dot(1, 2)` -> `dot: expected two vectors of the same size, got vector2 and vector3` / `got number and number`.
- `cross_is_the_vector3_product`: `cross(vector3(1,0,0), vector3(0,1,0))`
  tostring is `vector3(0.0, 0.0, 1.0)`; `pcall(cross, vec2(1,0), vec2(0,1))` ->
  `cross: expected two vector3, got vector2 and vector2`.
- `norm_scales_to_length_one_and_keeps_zero`: `tostring(norm(vector3(3,0,4)))`
  is `vector3(0.6, 0.0, 0.8)`; `tostring(norm(vector3(0)))` is
  `vector3(0.0, 0.0, 0.0)`; `#norm(quat(2,0,0,0)) == 1.0`; `pcall(norm, 5)` ->
  `norm: expected a vector or quat, got number`.
- `inv_inverts_a_quat`: `local q = quat(0.5,0.5,0.5,0.5); local r = q * inv(q)`;
  `r.w == 1.0`, `r.x == 0.0`; `pcall(inv, quat(0,0,0,0))` ->
  `inv: quat has zero length`; `pcall(inv, vector3(1))` ->
  `inv: expected a quat, got vector3`.
- `slerp_interpolates_quats`: `slerp(quat(1,0,0,0), quat(0,0,0,1), 0.0)` has
  `w == 1.0`; with `1.0` has `z == 1.0`; with `0.5` has `w` and `z` within
  1e-6 of `0.70710678` (compare via `math.abs(x - 0.70710678) < 1e-6` in Lua,
  return a boolean). `pcall(slerp, 1, 2, 3)` ->
  `slerp: expected (quat, quat, number), got number, number and number`.
- `vector_helpers_exist_on_the_client`: `new_client_host()` + `start` (see
  `get_hash_key_is_available_on_the_client`, line 446) returns
  `type(dot), type(vector)` = `function, function`.

# Spec D3: Live resource monitor (`resmon`), hitch warnings, and `/admin` panel

Add per-resource live performance monitoring (`resmon` console command, `GET /resmon.json`, and `/admin` live panel) plus configurable frame hitch warnings (`sixm_hitchWarningMs`) with **zero heap allocations on the hot path**.

## 1. Script runtime telemetry (`sixm-core`, `sixm-lua`, `sixm-js`)

- In `crates/sixm-core/src/runtime.rs`, add two default methods to `ScriptRuntime`:
  - `fn memory_bytes(&self) -> usize { 0 }`: returns the script VM's current allocator/heap usage in bytes (called off the hot path when querying `resmon`).
  - `fn handled_events(&self) -> u64 { 0 }`: cumulative count of script event listener invocations executed by this runtime.
- In `crates/sixm-lua/src/runtime.rs` & `events.rs`:
  - Add `handled_events: Cell<u64>` to `LuaRuntime` (or `Shared`), incremented for each invoked event handler in `run_handlers`.
  - Implement `ScriptRuntime::memory_bytes` returning `self.lua.used_memory()`, and `ScriptRuntime::handled_events` returning `self.handled_events.get()`.
- In `crates/sixm-js/src/runtime.rs` & `events.rs`:
  - Add `handled_events: Cell<u64>` to `JsRuntime`, incremented for each invoked event handler in `dispatch_event_in_ctx`.
  - Implement `ScriptRuntime::memory_bytes` returning `usize::try_from(self.rt.memory_usage().malloc_size.max(0)).unwrap_or(0)`, and `ScriptRuntime::handled_events` returning `self.handled_events.get()`.

## 2. Zero-allocation fixed ring buffer (`crates/sixm-server/src/perf.rs`)

Add `RESMON_WINDOW: usize = 60` and `ResourceMonitor` to `crates/sixm-server/src/perf.rs`:

- Fixed-size, `Cell`-backed (lock-free, zero-allocation on the single-threaded loop) struct:
  - `tick_micros: [Cell<u32>; RESMON_WINDOW]`
  - `event_counts: [Cell<u32>; RESMON_WINDOW]`
  - `head: Cell<usize>`
  - `filled: Cell<usize>`
  - `pending_events: Cell<u32>`
  - `total_events: Cell<u64>`
- Methods:
  - `pub(crate) const fn new() -> Self` (`Default` impl)
  - `pub(crate) fn add_events(&self, count: u64)`: saturating add into `pending_events` (`u32::MAX` clamp) and `total_events`. Zero allocation.
  - `pub(crate) fn record_frame(&self, tick: Duration)`: converts `tick.as_micros()` to `u32` (saturating at `u32::MAX`), writes `tick_micros` and `self.pending_events.replace(0)` at `slot = self.head.get()`, advances `head = (slot + 1) % RESMON_WINDOW`, updates `filled = (self.filled.get() + 1).min(RESMON_WINDOW)`. Zero allocation.
  - `pub(crate) fn stats(&self, heap_bytes: usize) -> ResourceResmonStats`:
    - `samples: usize` (`filled.get()`)
    - `avg_tick_micros: u64`
    - `max_tick_micros: u32`
    - `last_tick_micros: u32`
    - `window_events: u64` (sum of committed `event_counts` across `samples` + `pending_events.get()`)
    - `total_events: u64` (`total_events.get()`)
    - `heap_bytes: usize`
- Add unit tests in `perf.rs` verifying wrap-around past `RESMON_WINDOW`, saturating addition, average/max computation, and pending event flush.

## 3. Resource manager & server tick integration (`crates/sixm-server/src/manager.rs`, `server.rs`, `convars.rs`)

- **Convar `sixm_hitchWarningMs`** in `crates/sixm-server/src/convars.rs`:
  - `const HITCH_WARNING_MS: &str = "sixm_hitchwarningms";` (stored lowercase so hot-path `self.values.get(HITCH_WARNING_MS)` never allocates).
  - Seed in `Convars::new()` with `"50"` (50 ms matches the default 20 TPS budget; `0` disables warnings).
  - Add `pub(crate) fn hitch_warning_ms(&self) -> u64`: parses trimmed string as `u64`, falls back to `DEFAULT_HITCH_WARNING_MS` (`50`) if non-numeric or missing; clamp upper bound at e.g. `60_000`. Wait: `0` is allowed to disable. Add unit test in `convars.rs`.
- **Hitch warning in `Server::tick`** (`crates/sixm-server/src/server.rs`):
  - After `let elapsed = started.elapsed(); self.manager.frames.borrow_mut().record(elapsed);`:
  - Read `let threshold_ms = self.manager.convars.borrow().hitch_warning_ms();`
  - If `threshold_ms > 0 && elapsed >= Duration::from_millis(threshold_ms)`:
    log `warn!("server frame hitch: {} ms exceeds sixm_hitchWarningMs ({} ms)", format_millis(u64::try_from(elapsed.as_micros()).unwrap_or(u64::MAX)), threshold_ms);`.
- **Per-resource monitor & zero-allocation snapshots in `manager.rs`:**
  - `RunningResource` holds `name: ResourceName`, `runtimes: Vec<Rc<dyn ScriptRuntime>>`, and `monitor: Rc<ResourceMonitor>`.
  - Cache two slices rebuilt ONLY in `rebuild_snapshot()` (when `running` changes):
    - `snapshot: RefCell<Rc<[RuntimeSlot]>>` where `RuntimeSlot { runtime: Rc<dyn ScriptRuntime>, monitor: Rc<ResourceMonitor> }` (used by `dispatch_from`).
    - `resource_snapshot: RefCell<Rc<[ResourceTickGroup]>>` where `ResourceTickGroup { name: ResourceName, monitor: Rc<ResourceMonitor>, runtimes: Rc<[Rc<dyn ScriptRuntime>]> }` (used by `tick_all` and `resmon_snapshot()`).
  - In `tick_all(now)`: iterate `resource_snapshot` (`Rc::clone` — zero alloc). For each resource group: record `start = Instant::now()`, tick all its runtimes (if `profiling`, record profiler span per runtime), then call `group.monitor.record_frame(start.elapsed())`. Zero heap allocations per frame.
  - In `dispatch_from`: when calling `slot.runtime.dispatch(...)`, check `let before = slot.runtime.handled_events();`, dispatch, then `let delta = slot.runtime.handled_events().saturating_sub(before); if delta > 0 { slot.monitor.add_events(delta); }`. Also count queued/deferred JS pending events? Keeping `handled_events()` updated inside `dispatch_event_in_ctx` (and JS `drain_pending_events`) captures all listener invocations accurately; check delta across `tick(now)` as well? Adding `let before = runtime.handled_events(); runtime.tick(now); let delta = runtime.handled_events().saturating_sub(before); if delta > 0 { group.monitor.add_events(delta); }` in `tick_all` catches any local `emit` / deferred JS events run during `tick` too!
  - Expose `pub(crate) fn resmon_snapshot(&self) -> Vec<(ResourceName, ResourceResmonStats)>` on `ResourceManager`, summing `runtime.memory_bytes()` across runtimes of each running resource.

# Spec A6: category commands and `server_only`

No `sixm-core` change. Server console only; no script API.

## Names (checked in `sources/server-manual.md` l.39-42, `scripting-manual.md` l.18-19, `scripting-reference.md` l.34)

`start`, `stop`, `restart`, `ensure` with a `[category]` argument, and the manifest key `server_only`
("prevents clients from downloading resource files") are documented. The accepted value of
`server_only` is **not** in `sources/`; PLAN says `'yes'`. SixM follows `lua54`: the text `yes` is true,
every other text is false. A boolean (`server_only true`) is already refused by the manifest parser
(`scalar`, `manifest.rs:240`, error `UnsupportedValue`); do not change that. Nothing is dropped.

## Categories (`crates/sixm-resources/src/catalog.rs`)

A category is a folder whose name starts with `[` and ends with `]` (`is_category`, l.343). Its name
is the folder name **with** the brackets, matched exactly (case-sensitive). A resource belongs to every
category on its path: `[a]/[b]/res` is in `[a]` and in `[b]`. `[a]` also contains the resources of `[b]`.

1. `Catalog` gets `categories: BTreeMap<String, Vec<ResourceName>>` (members in scan order).
2. `scan_dir` gets a parameter `path: &mut Vec<String>`; `scan` passes an empty one. In the category
   branch: `path.push(folder name)`, `categories.entry(name).or_default()` (so an empty category exists),
   recurse, `path.pop()`. `add_resource` gets `path: &[String]` and, in the `Entry::Vacant` branch only
   (a duplicate is not added), pushes the name to `categories[c]` for each `c` in `path`.
3. New public methods (doc comments in the file's style):
   - `pub fn is_category(&self, name: &str) -> bool`
   - `pub fn category_members(&self, name: &str) -> Option<&[ResourceName]>` (scan order, `None` if unknown)
   - `pub fn category_start_order(&self, name: &str) -> Result<Option<Vec<ResourceName>>, DependencyError>`:
     `None` if unknown; else for each member in scan order extend with `start_order(member)?`, skipping
     names already present. Result: members plus their dependencies, dependencies first, each once.
4. Rename nothing; the private `is_category(path)` helper stays (different signature, no clash because
   the method is on `Catalog`).

## Manager (`crates/sixm-server/src/manager.rs`)

Add `ManagerError::UnknownCategory(String)` with `#[error("no resource category `{0}`")]` (the string
is the name as typed, brackets included). Add four public methods, each starting with
`self.ensure_scanned();`:

- `start_category(&self, category) -> Result<(), ManagerError>`: `category_start_order`; unknown ->
  `UnknownCategory`; for each name in order: `if !self.is_running_canonical(n) { self.start_one(n)? }`
  (the same body as `start`). An empty category logs `warn!("category `{category}` has no resources")`
  and returns `Ok`.
- `stop_category`: members = `category_members`; order them by dependency with
  `start_order` restricted to members, **reversed** (dependents before dependencies); for each that is
  running call `self.stop(n)?`; members not running are skipped silently. `stop` also stops running
  dependents outside the category (as for a single resource). Empty: same warn.
- `restart_category`: for each member in dependency order (the `start_order` walk above, members only,
  not reversed) call `self.restart(n)?` (not running -> started, as `restart` does today).
- `ensure_category`: for each member in the same order call `self.ensure(n)?` (restart if running,
  else start). Because `restart(A)` restarts running dependents, a member that depends on an earlier one
  may restart twice; this is accepted and documented.
All four stop at the first error (like a failing `start` chain); the error is logged by `report`.
Helper `fn members_in_dependency_order(&self, category) -> Result<Vec<ResourceName>, ManagerError>` shared by
stop/restart/ensure (filter `category_start_order` by membership).

## Commands (`crates/sixm-server/src/commands.rs`, l.144-151)

Add `fn is_category_arg(arg: &str) -> bool { arg.len() > 2 && arg.starts_with('[') && arg.ends_with(']') }`.
Each of the four closures becomes `if is_category_arg(r) { manager.<verb>_category(r) } else { manager.<verb>(r) }`.
The bracketed form is always a category (a resource folder literally named `[x]` is not addressable by
these four commands). Usage strings become `start <resource|[category]>` etc. In `report` (l.383) treat
`UnknownCategory` like `NotRunning`: `warn!`. ACE objects (`command.start`...) are unchanged.

## `server_only`

- `Manifest` (`manifest.rs:58`) gets `pub server_only: bool` ("Whether clients never receive the
  resource"). In `build` (l.269): `"server_only" => { manifest.server_only = value == "yes"; manifest.metadata.push((key, value)); }`
  (kept in `metadata` too so `GetResourceMetadata('x','server_only')` still works).
- Effect, in `ResourceManager` (`manager.rs:822-845`):
  - `advertise`: at the top, if the catalog entry of `name` has `manifest.server_only`, `return` before
    building the entry: no file list, no `broadcast_resource_started`, so clients never see the resource,
    its exports, its metadata or its scripts, and the client never loads `client_scripts`/`shared_scripts`
    of it.
  - `withdraw`: compare `advertised.len()` before and after the `retain`; return early when nothing was
    removed (so a stop of a server-only resource, or one whose manifest changed after `refresh`, sends no
    `broadcast_resource_stopped`).
- The resource still runs on the server and its server scripts, exports and `provide` aliases work.
  Client resources have no dependency data, so a server-only dependency changes nothing on clients.
  A `@server_only_res/file` pattern in another resource's `client_scripts`/`files` is still expanded
  by `client_files` (the file travels as part of the *other* resource); that is the author's choice and
  is documented.

# Spec D1: Console commands

Add FiveM operator console commands `status`, `clientkick`, built-in `say`, `cmdlist`, and `exec @resource/file.cfg` in `crates/sixm-server/src/commands.rs`.

## Commands

Update `BUILT_IN` (`pub(crate) const BUILT_IN: [&str; 33]`, sorted) to include `"clientkick"`, `"cmdlist"`, `"say"`, and `"status"` (`"exec"` is already present). All built-in commands check `permitted(manager, &context.source, &lower)` (`command.<name>` ACE for `Player` and `Resource` sources; `Console` is always permitted).

1. **`status`**:
   - Reject extra arguments with `warn!("usage: status")`.
   - Log server summary (`server: <server_name>, resources: <running>/<total>, players: <connected>/<max_clients>`).
   - If connected players exist, log each connected player in join order with id, name, round-trip ping in ms (from `manager.player_round_trip(id)`, or `"-"` if unavailable), identifiers (`manager.identifiers_of(id)` joined with `", "`), and endpoint.
2. **`clientkick <id> [reason]`**:
   - Require `<id>` as positive `u32`; invalid usage logs `warn!("usage: clientkick <id> [reason]")`.
   - Verify the player is currently connected (`manager.player_ids().contains(&id)` and `manager.player_details(id).is_some()`); unknown id logs `warn!("clientkick: unknown player {id}")`.
   - Default reason when omitted: `"Kicked from server"`; otherwise `args[1..].join(" ")`.
   - Queue drop via `manager.queue_drop(id, &reason, origin)` where `CommandSource::Resource(res)` uses `(res.to_string(), DROP_SCRIPT)` and `Console`/`Player` use `(String::new(), DROP_SERVER)`.
3. **Built-in `say <text>`**:
   - Require at least one non-empty cleaned argument (`args.join(" ")`, control characters replaced with spaces, trimmed). Empty logs `warn!("usage: say <text>")`; `> 256` bytes logs `warn!("say: message exceeds 256 bytes")` and returns.
   - Author: `player = 0, author = "Console"` for `Console` and `Resource(_)`; for `Player(id)`, look up `player_details(id)` (return if unknown) and clean control chars in name.
   - If `manager.resource_state("chat") == ResourceState::Started`:
     - Dispatch local cancelable `chatMessage(player, author, message)`.
     - If not canceled, log `info!("{author}: {message}")` and call `manager.send_client_event("chat:addMessage", ClientTarget::All, &[Value::Map(vec![(Value::from("args"), Value::Array(vec![Value::from(author), Value::from(message)]))])])` (log on send error).
   - Otherwise (when `chat` is not running): log `info!("{author}: {message}")`.
   - Remove the shadowed `RegisterCommand('say', ...)` from `examples/server-data/resources/[system]/chat/server.lua`; `"say"` remains in `BUILT_IN` so `GetRegisteredCommands()` / `chat:init` still includes `"/say"`.
4. **`cmdlist`**:
   - Reject extra arguments with `warn!("usage: cmdlist")`.
   - Log all built-in commands (sorted) and all registered script commands (`manager.script_commands()`, sorted, marking `(restricted)` where applicable).
5. **`exec @resource/file.cfg`**:
   - In `exec`, if `file` starts with `'@'`:
     - Split `<resource>` and `<relative_path>` at the first `'/'` or `'\\'` after `'@'`; reject missing separator or empty part with `error!`.
     - Validate `<relative_path>` via `normalize_resource_path`; reject invalid paths with `error!`.
     - Resolve resource directory via `manager.resource_path(resource)` (supports `provide` aliases); unknown resource logs `error!`.
     - Read via `ResourceDirectory::open(&dir)?.read(&normalized)` so symlinks, path traversal, and invalid filenames are rejected on both Windows and Linux.
   - Run tokenized lines with `context.depth >= MAX_EXEC_DEPTH` and `&context.nested()`, preserving permissions (`CommandSource`).

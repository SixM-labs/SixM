# Spec A5: missing server events and arguments

Lua and JS need no code change: events are delivered by the host through `dispatch`, the
runtimes already pass any `Value` args. One `sixm-core` trait change (below).

## Names (checked against `sources/scripting-reference.md` l.59-83 and `scripting-manual.md` l.258-260)

- `onResourceListRefresh` (no params): documented.
- `playerJoining` (`source`, `oldID`): documented. `playerDropped` (`source`, `reason`,
  `resourceName`, `clientDropReason`): documented.
- `onEntityBucketChange(entity, bucket, oldBucket)`: documented.
- `onPlayerBucketChange`: listed in the manual, but the reference says "listed in nav only,
  not documented". **Its argument list is SixM's choice** (PLAN A5): `(player, bucket, oldBucket)`.
  Nothing is dropped.
- `clientDropReason` values are **not in `sources/`**. The numbers below are SixM's own; do
  not claim FiveM compatibility for them in the docs.

## Decided behavior

| Event | Source | Args (Lua/JS values) |
|---|---|---|
| `onPlayerBucketChange` | `EventSource::Local` | `player` (decimal **string**, like `GetPlayers`), `bucket` (int), `oldBucket` (int) |
| `onEntityBucketChange` | `EventSource::Local` | `entity` (int id), `bucket` (int), `oldBucket` (int) |
| `onResourceListRefresh` | `EventSource::Local` | none |
| `playerJoining` | `EventSource::Player(id)` (unchanged) | `oldID` = the id as a decimal **string** |
| `playerDropped` | `EventSource::Player(id)` (unchanged) | `reason` (string, as now), `resourceName` (string), `clientDropReason` (int) |

Bucket events:
- Fired only when the bucket really changes: `SetPlayerRoutingBucket(p, same)` and
  `SetEntityRoutingBucket(e, same)` fire nothing. An unknown player or entity (the `route_*` call
  returns `false`) fires nothing.
- Fired after the move is complete (scopes settled), so handlers see the new state
  (`GetPlayerRoutingBucket` already returns `bucket`).
- Entity events fire for every entity kind (ped, vehicle, object) and for client-created
  entities, because they all go through `route_entity`.
- Moving a player also moves its ped. Order: `onPlayerBucketChange` first, then
  `onEntityBucketChange` for the ped, only if the ped's own bucket was different before
  (read it with `routed_entity(ped)` before the move). A player without a ped fires no entity event.
- `playerJoining`: SixM assigns the player id before `playerConnecting` and keeps it, so
  `oldID` always equals `source` (FiveM has a temporary id there). Document this.
- `onResourceListRefresh` fires at the end of `ResourceManager::refresh` (so also for the
  hot-reload watcher), after the catalog is replaced.

`clientDropReason` (and `resourceName`) per drop path:

| Path | `resourceName` | `clientDropReason` |
|---|---|---|
| Client closed or lost the connection (`NetEvent::Disconnected` without a kick of ours, `abandoned` -> `"connection closed"`) | `""` | `0` |
| `DropPlayer` from a script (kick applied by `apply_drops`) | name of the calling resource | `1` |
| Kick the server decides (`client_entities.rs:80` `"entity id out of lease"`) | `""` | `2` |

## sixm-core change

`ServerHost::drop_player` (`crates/sixm-core/src/runtime.rs:445`) gets the caller:
```rust
/// Disconnects a player with a reason shown to them. `resource` is the resource that asked;
/// `playerDropped` reports it. Takes effect after the current script call returns.
fn drop_player(&self, player: u32, reason: &str, resource: &str);
```
Update every implementor and caller: `sixm-server/src/manager.rs:1433` (`self.queue_drop(player,
reason, Some(resource))`), `sixm-lua/src/players.rs:83` (pass `&rt.resource`),
`sixm-js/src/players.rs:338` (same), test hosts `sixm-lua/tests/common/mod.rs:476` and
`sixm-js/tests/common/mod.rs:473`: change `dropped: RefCell<Vec<(u32, String)>>` to
`Vec<(u32, String, String)>` (player, reason, resource) and fix `sixm-lua/tests/players.rs:234`
(and the JS twin) to expect the resource name of the test resource as third element.

## Server code

1. `crates/sixm-server/src/network.rs`:
   - Add `pub(crate) struct DropOrigin { pub(crate) resource: String, pub(crate) code: i64 }`
     (`Debug, Clone`) with consts `DROP_CLIENT: i64 = 0`, `DROP_SCRIPT = 1`, `DROP_SERVER = 2`
     and doc comments naming the three paths above.
   - `Network` (l.285): change `pending_drops` to `RefCell<Vec<(u32, String, DropOrigin)>>`; add
     `drop_origins: RefCell<HashMap<u32, DropOrigin>>` (`Network` derives `Default`).
   - `queue_drop(&self, player, reason, origin: DropOrigin)` (l.1032); update its caller
     `client_entities.rs:80` with `DropOrigin { resource: String::new(), code: DROP_SERVER }`.
   - `apply_drops` (l.1041): for each queued drop, only if `self.network.players.borrow().contains(player)`,
     `drop_origins.borrow_mut().entry(player).or_insert(origin)`, then kick as now.
   - `player_dropped` (l.859): `let origin = self.network.drop_origins.borrow_mut().remove(&player);`
     before dispatching (always, so the map never keeps stale entries). Dispatch args:
     `[Value::from(reason), Value::from(origin.resource), Value::Int(origin.code)]`, defaulting to
     `("", DROP_CLIENT)` when `origin` is `None`. Update its doc comment.
   - `admit` (l.703): `&[Value::from(id.to_string())]` instead of `&[]`.
2. `crates/sixm-server/src/manager.rs`: add next to `dispatch` (l.679)
   `pub(crate) fn has_handler(&self, event: &str) -> bool { self.snapshot().iter().any(|rt| rt.handles_event(event)) }`
   (clones one `Rc`, no allocation). At the end of `refresh` (l.293, after `self.scanned.set(true)`):
   `self.dispatch("onResourceListRefresh", EventSource::Local, &[]);`.
3. `crates/sixm-server/src/buckets.rs`: constants `PLAYER_BUCKET_EVENT = "onPlayerBucketChange"`,
   `ENTITY_BUCKET_EVENT = "onEntityBucketChange"`. Rewrite `route_player` / `route_entity`:
   read `old` (`routed_player` / `routed_entity`) first (return `false` if `None`), read the ped and
   its old bucket, do the existing move, then if `old != bucket` and `self.has_handler(EVENT)`
   dispatch with `EventSource::Local`. Build the `Value` args only inside the `if` (no allocation
   without handlers). Entity ids: `Value::Int(i64::from(id))`. Update the module doc.

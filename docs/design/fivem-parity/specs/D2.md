# Spec D2: Console channel filters

Add FiveM console channel filtering commands `con_channelFilters`, `con_addChannelFilter <channel> <action>`, and `con_removeChannelFilter <channel>` in `crates/sixm-server`.

## Channel filter store (`crates/sixm-server/src/logging.rs` or `filters.rs`)

- Create a thread-safe `ChannelFilters` handle (`Clone`, `Debug`, `Default`) backed by:
  - `has_filters: Arc<AtomicBool>` for a lock-free, allocation-free fast path when no filters are active.
  - `rules: Arc<RwLock<Vec<ChannelRule>>>` storing `{ pattern: String, action: ChannelAction }` where `ChannelAction` is `Print` (`"print"`) or `None` (`"none"`).
- `ChannelAction::parse(word)`: accepts `"print"` (`ChannelAction::Print`) and `"none"` (`ChannelAction::None`) case-insensitively.
- Operations on `ChannelFilters`:
  - `set(&self, channel: &str, action: ChannelAction)`: replaces an existing rule matching `channel` (ASCII case-insensitive) or pushes a new rule; updates `has_filters`.
  - `remove(&self, channel: &str) -> bool`: removes an existing rule matching `channel` (ASCII case-insensitive); updates `has_filters` and returns whether one was removed.
  - `list(&self) -> Vec<(String, ChannelAction)>`: snapshot of active rules in insertion order.
  - `allows(&self, target: &str, message: Option<&str>) -> bool`:
    - Fast path: if `!self.has_filters.load(Ordering::Relaxed)`, return `true`.
    - Otherwise read `rules` and evaluate in order (last matching rule wins; default `Print` if none match).
    - A rule `pattern` matches if `convar_filter_matches(&rule.pattern, target)` is true, OR (when `target == "sixm::script"` and `message` begins with `"[<resource>] "` or `"[<resource>]"`) `convar_filter_matches(&rule.pattern, &format!("script:{resource}"))` (without allocating when checking — compare prefix `"script:"` + slice or check `matches_script_channel`).
- Expose `pub fn tracing_filter(&self) -> ...` (a `tracing_subscriber::layer::Filter<S>` for `crates/sixm-server/src/main.rs`) and integrate into `capture_logs` in `crates/sixm-server/src/web.rs` so both process stdout/file logs and `/rcon` captured logs honor the server's `ChannelFilters`.
- Expose `Server::with_channel_filters(filters: ChannelFilters)` and `pub fn channel_filters(&self) -> &ChannelFilters` on `Server` (and `ResourceManager`), while `Server::new()` creates a fresh isolated `ChannelFilters` so tests run independently in parallel.
- Update `crates/sixm-server/src/main.rs`: pass `filters.tracing_filter()` to `init_logging` and construct `Server::with_channel_filters(filters)`.

## Console commands (`crates/sixm-server/src/commands.rs`)

Add `"con_addchannelfilter"`, `"con_channelfilters"`, `"con_removechannelfilter"` to `BUILT_IN` (`[&str; 36]`, strictly sorted). `run_words` lowercases command names before lookup, so camelCase `con_channelFilters`, `con_addChannelFilter`, and `con_removeChannelFilter` work and check `command.<name>` ACE permissions for non-console sources.

1. **`con_channelFilters`**:
   - Reject extra args (`warn!("usage: con_channelFilters")`).
   - Print active rules as `channel filter <pattern> -> <print|none>`, or `No console channel filters active` when empty.
2. **`con_addChannelFilter <channel> <action>`**:
   - Require 2 non-empty args (`warn!("usage: con_addChannelFilter <channel> <print|none>")`).
   - Parse `<action>` (`print` or `none`, case-insensitive; warn usage on invalid action).
   - Store via `manager.channel_filters().set(channel, action)` and log `channel filter {channel} -> {action}`.
3. **`con_removeChannelFilter <channel>`**:
   - Require 1 non-empty arg (`warn!("usage: con_removeChannelFilter <channel>")`).
   - Remove via `manager.channel_filters().remove(channel)` and log `removed channel filter {channel}` or `warn!("no channel filter for {channel}")`.

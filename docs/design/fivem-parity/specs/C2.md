# Spec C2: Client-written state bags — script side

Client scripts (`LocalPlayer.state`, `Entity(owned).state`, and `SetStateBagValue`) may write replicated keys (`replicated = true` or default on `bag:set` / property assignment) to their own player bag and to entities owned by the local client.

## Client runtime (`crates/sixm-client/src/host.rs`)

Update `impl Host for ClientRuntime` -> `state_set(&self, bag: &str, key: &str, value: Value, replicated: bool) -> Result<(), ScriptError>`:
1. Validate `validate_key(key)?` and reject `value.contains_func_ref()` with `"state values cannot contain functions"`.
2. If `replicated`:
   - Allow only:
     - `player_of_bag(bag) == Some(self.local_player)`
     - OR `entity_of_bag(bag).is_some_and(|entity| self.entities.borrow().get(&entity).is_some_and(|slot| slot.info.owner == Some(self.local_player)))`
   - Otherwise:
     - If `!self.bag_exists(bag)`, return `Err(ScriptError::Runtime(format!("state bag `{bag}` does not exist")))`.
     - Else return `Err(ScriptError::Runtime("clients can only write replicated state to their own player or owned entities".to_owned()))`.
   - Send to the server BEFORE mutating local state:
     `self.client.borrow().send_state(bag, key, &value).map_err(|err| ScriptError::Runtime(err.to_string()))?;`
3. Else (`!replicated`):
   - Check `self.bag_exists(bag)` as before; return `state bag \`{bag}\` does not exist` if missing.
4. Apply locally and fire client change handlers:
   - `self.state.borrow_mut().apply(bag, key, &value);`
   - `self.deliver_state(bag, key, &value, replicated);`

Note:
- Both Lua (`crates/sixm-lua/src/state.rs`, `client.rs`, `entities.rs`) and JS (`crates/sixm-js/src/state.rs`, `client.rs`, `entities.rs`) route `LocalPlayer.state`, `Entity(id).state`, and `SetStateBagValue` through `Host::state_set`.
- JS `skip_self_state` avoids double-delivering to the calling JS runtime while still notifying other runtimes on the same client via `deliver_state`.
- Because the server relays with `except = Some(player)` (C1), the originating client receives immediate local mirror + local change handler delivery (`replicated = true`) without receiving a duplicate echo from the server, while server runtimes and other holding clients fire their change handlers when the relay arrives.

## Docs, types, and tests

- `docs/guides/from-fivem.md`: remove `"Clients cannot write replicated state"` and document client-written replicated state on `LocalPlayer.state` and owned `Entity(id).state` (while `GlobalState`, other players' bags, and unowned entities remain local-only or server-written, and `sv_stateBagStrictMode` disables client writes server-side).
- `docs/lua-api.md` & `docs/js-api.md`: update state bag sections (`LocalPlayer.state`, `Entity(id).state`, `SetStateBagValue`) to reflect client replicated writes on own player and owned entities, and server-enforced `sv_stateBagStrictMode`.
- `types/sixm.lua` & `types/sixm.d.ts`: verify comments on state bag APIs do not claim client replicated writes always error.
- `crates/sixm-server/tests/state.rs`: end-to-end Lua and JS client tests verifying:
  - `LocalPlayer.state.k = v`, `LocalPlayer.state:set(k, v, true)`, `nil` / `delete` removal, and `SetStateBagValue` from Lua and JS update local state immediately, fire change handlers on server and other client (`replicated = true`), and do not double-fire on the originating client.
  - `Entity(owned).state:set(k, v, true)` for client-owned entities (both client-created and server-transferred) replicates to server and holding clients, respecting scoping.
  - Client replicated writes to `GlobalState`, another player's bag, or an unowned entity raise a script error without changing server state or other clients.
  - `sv_stateBagStrictMode true` prevents client writes from updating server state or relaying to other clients.
- `CHANGELOG.md`: update Unreleased entry if needed.

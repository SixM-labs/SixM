# Spec A7: `baseevents` with FiveM names

No code, no `sixm-core` change, no new native. Only the example resource and docs.

## Names (checked in `sources/ecosystem.md` l.72-73 and `scripting-reference.md` l.51)

`sources/` lists exactly these channels, all prefixed `baseevents:`: `onPlayerWasted`, `onPlayerKilled`,
`onPlayerDied`, `enteringVehicle`, `enteringAborted`, `enteredVehicle`, `leftVehicle`. **It gives no argument
lists.** The lists below are the documentation-level FiveM signatures (names and order only; they are
comments, SixM does not validate them). Say so in the file header: "argument lists as documented for
FiveM; SixM never emits these itself yet".

**Removed (SixM-only, no FiveM equivalent):** `baseevents:onPlayerEnteredVehicle` (replaced by
`baseevents:enteredVehicle`) and `baseevents:onPlayerLeftVehicle` (replaced by `baseevents:leftVehicle`).
`baseevents:onPlayerDied` stays. Nothing else in the repository registers or listens to the old names
(grep confirmed: only the three doc places below).

## File: `examples/server-data/resources/[system]/baseevents/server.lua`

Stays a pure channel registration: the `EVENT_CHANNELS` table plus the `for ... RegisterNetEvent(name)`
loop, no handlers, no emitters. Replace the header comment and the table with:

```lua
-- Clean-room base gameplay event channels, with the FiveM names.
--
-- SixM's headless core has no GameAdapter that emits vehicle seating or
-- death events. A client script (or a future adapter) sends these with
-- TriggerServerEvent; the channels are registered so that the server
-- accepts them and AddEventHandler listeners receive them. `source` is
-- the player. Argument lists, as documented for FiveM (the tables are
-- plain Lua tables):
--
--   * `baseevents:onPlayerDied(killerType, deathCoords)`
--   * `baseevents:onPlayerKilled(killerId, data)`
--       data = { killertype, weaponhash, killerinvehicle, killervehseat,
--                killervehname, killerpos }
--   * `baseevents:onPlayerWasted(deathCoords)`
--   * `baseevents:enteringVehicle(vehicle, seat, displayName, netId)`
--   * `baseevents:enteringAborted()`
--   * `baseevents:enteredVehicle(vehicle, seat, displayName, netId)`
--   * `baseevents:leftVehicle(vehicle, seat, displayName, netId)`

local EVENT_CHANNELS = {
    'baseevents:onPlayerDied',
    'baseevents:onPlayerKilled',
    'baseevents:onPlayerWasted',
    'baseevents:enteringVehicle',
    'baseevents:enteringAborted',
    'baseevents:enteredVehicle',
    'baseevents:leftVehicle',
}
```
Keep the existing `for _, eventName in ipairs(EVENT_CHANNELS) do RegisterNetEvent(eventName) end` loop
unchanged. Do not touch `fxmanifest.lua` (its `description` stays; `server_script 'server.lua'` stays).
Style: 4-space indent, single quotes, trailing comma, like the current file.

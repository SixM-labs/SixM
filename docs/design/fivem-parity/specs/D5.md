# Spec D5: `deferrals.presentCard`

Implement FiveM-compatible Adaptive Card deferrals (`deferrals.presentCard(card, cb?)`) across `sixm-net`, `sixm-server`, and `sixm-client`, with protocol version bump (`15 -> 16`).

## 1. Protocol & wire format (`crates/sixm-net`)

- **`crates/sixm-net/src/protocol.rs`**:
  - Bump `PROTOCOL_VERSION: u32` from `15` to `16`.
  - Add constants:
    - `pub const MAX_CARD_BYTES: usize = 64 * 1024;`
    - `pub const MAX_CARD_RESPONSE_BYTES: usize = 64 * 1024;`
  - Add `ServerMessage::PresentCard { id: u64, card_json: String }` (during handshake while connection is pending).
  - Add `ClientMessage::CardResponse { id: u64, data_json: Option<String> }` (`None` = canceled/dismissed, `Some(json)` = submitted JSON payload).
  - Update `ServerMessage` / `ClientMessage` variant indices cleanly in `wire.rs` & `fuzz_tests.rs`.
- **`crates/sixm-net/src/wire.rs`**:
  - Encode/decode `PresentCard` and `CardResponse`, enforcing `MAX_CARD_BYTES` / `MAX_CARD_RESPONSE_BYTES` limits cleanly on decode (refuse oversized frames as malformed).
  - Add roundtrip & cap unit tests in `wire.rs` and update `fuzz_tests.rs`.
- **`crates/sixm-net/src/server.rs`**:
  - Add `NetEvent::CardResponse { connection: ConnectionId, id: u64, data_json: Option<String> }`.
  - Add `pub fn present_card(&self, connection: ConnectionId, id: u64, card_json: &str) -> Result<(), NetError>` sending `ServerMessage::PresentCard { id, card_json }` to a pending (deferred) connection (checking size cap `<= MAX_CARD_BYTES`).
  - Handle incoming `ClientMessage::CardResponse` from a pending connection on the server connection task and forward as `NetEvent::CardResponse`.
- **`crates/sixm-net/src/client.rs`**:
  - Keep existing `NetClient::connect` and `NetClient::connect_observed` signatures compatible (forwarding to a shared internal helper where default `on_card` cancels cards with `None` so non-interactive clients don't hang).
  - Add `pub fn connect_with_card_handler(..., on_deferral: impl FnMut(&str), on_card: impl FnMut(&str) -> Option<String>) -> Result<NetClient, NetError>`.
  - Inside `greet()`:
    - On `ServerMessage::Deferral { message }`: invoke `on_deferral(&message)` and refresh `deadline`.
    - On `ServerMessage::PresentCard { id, card_json }`: invoke `let data_json = on_card(&card_json);`, write `ClientMessage::CardResponse { id, data_json }` on `send`, and refresh `deadline = Instant::now() + timeout`.
  - Ensure both Linux and Windows paths work cleanly without blocking forever when `None` or connection drop happens.

## 2. Server `deferrals.presentCard` (`crates/sixm-server/src/network.rs`)

- Extend `DeferralCall` with `PresentCard { id: u64, card_json: String, callback: Option<FuncRef> }`.
- Extend `Player`:
  - `next_card_id: u64` (or per-network monotonic `AtomicU64`/counter) and `card_callbacks: HashMap<u64, FuncRef>`.
  - Release any remaining `card_callbacks` in BOTH `admit()` and `end_pending()` via `self.release_functions(...)`.
- Expose `presentCard` on the `playerConnecting` `deferrals` map in `run_connecting`:
  - **Lifecycle:** Unlike `setKickReason`/`defer`, keep `presentCard`'s `FuncRef` in `player.functions` (alongside `update` and `done`) so async deferral timers/HTTP callbacks can present cards while deferred.
  - **Arguments:** `presentCard(card, cb?)` accepts:
    - Argument 1 (`card`): `Value::String` (validated with `serde_json::from_str::<serde_json::Value>` and `len <= MAX_CARD_BYTES`, returning `ScriptError::Runtime` on invalid JSON or oversize) OR `Value::Map` (converted to JSON and serialized, returning `ScriptError::Runtime` on unconvertible keys or oversize). Note: in JS/Lua passing a JS object / Lua table or JSON string both work!
    - Argument 2 (`cb`, optional `Nil` or omitted or `Value::FuncRef`): when `FuncRef` is provided, retain it on the host (`retain_function` or stored directly by `Value::FuncRef` — wait: check `sixm-lua`/`sixm-js` `Value::FuncRef` lifetime so the callback stays retained until queued/released!). Note: `host_fn` args already clone `FuncRef` cleanly; retain `cb` via `manager.retain_function` or keep it registered until `CardResponse` / cleanup! Verify exact `FuncRef` ownership in `host_functions.rs` / `manager.rs`.
- In `apply_deferral_call` (`DeferralCall::PresentCard`):
  - Check player is `!found.admitted && found.deferral.is_some()`.
  - If `Some(cb)`, insert `(id, cb)` into `found.card_callbacks`.
  - Refresh `deferral.since = Instant::now()`.
  - Call `server.present_card(connection, id, &card_json)`.
- Handle `NetEvent::CardResponse { connection, id, data_json }` in `handle_net`:
  - Resolve pending player by `connection`. If not pending or missing, ignore.
  - Refresh `deferral.since = Instant::now()`.
  - Take `callback` from `player.card_callbacks.remove(&id)`.
  - If `Some(cb)`:
    - Convert `data_json`:
      - If `Some(raw)` parses as JSON: `(json_to_value(&parsed), Value::from(raw.as_str()))`. If `raw` isn't valid JSON, ignore/warn or pass `(Value::Nil, Value::from(raw.as_str()))`.
      - If `None` (client canceled): `(Value::Nil, Value::Nil)`.
    - Invoke `self.call_ref(&cb, &[data, raw_data])`, release `cb` (`self.release_functions(&[cb])`), then call `self.apply_deferral_calls()` and `self.settle(player_id)`.

## 3. Headless CLI client (`crates/sixm-client/src/main.rs`)

- Connect using `Client::connect_with_card_handler(...)`.
- Reuse the already-spawned `input: Receiver<Input>` channel (do NOT spawn a second stdin reader):
  - When a card arrives during `connect_with_card_handler`, log a readable summary (`info!`) with the card title/body (if JSON object) and full JSON, prompt the user cleanly (`Enter JSON response, 'cancel', or press Enter for {}:`), and wait on `input.recv_timeout(CONNECT_TIMEOUT)`:
    - `Input::Quit(_)` or channel closed or `"cancel"` (case-insensitive): return `None`.
    - Empty trimmed line: return `Some("{}".to_owned())`.
    - Valid JSON object/value line: return `Some(trimmed.to_owned())`.
    - Non-JSON input line: warn and re-prompt until valid JSON, `"cancel"`, quit, or timeout (returning `None` on timeout).
- Buffer or discard? Note `spawn_stdin_reader` only sends `Input::Line` / `Input::Quit`, so no other messages exist on `input` before connection succeeds.

# SixM vs FiveM gap report

Inputs: the catalogues in `sources/` vs `sixm-inventory.md` and `native-coverage-summary.md` (research of 2026-11-27, commit a752a53). Every "missing" claim was grep-checked in `crates/`, `docs/`, `types/`, `examples/`. [game] items are only counted (section 4). Effort: S = under a day, M = days, L = weeks.

Verified OK (no gap): routing bucket natives (all 9 present), KVP (all 15 server+client names), convar getters/setters/listeners, `RegisterCommand` with restricted flag, `ExecuteCommand` (stricter on purpose), latent events, state bag change handlers, `provide`, `@res/` manifest refs, `dependency '/server:x'` parses (ignored, not an error), hot reload, profiler record/stop/status/saveJSON, IDE types (every registered global name is declared in `types/sixm.lua` and `types/sixm.d.ts`, except the `--sim` natives).

## 1. P1 - hit immediately when porting ESX/QBCore/ox_lib-style resources

1. **Client-written replicated state bags**: `LocalPlayer.state:set(k, v, true)`, `Entity(owned).state:set(..., true)` from a client. SixM raises "clients cannot write replicated state" (`crates/sixm-client/src/host.rs:251`). FiveM lets the owning player write its own player/entity bags; the server relays. Also `sv_stateBagStrictMode` (server-only writes) does not exist. Where: protocol message in `sixm-net`, accept/validate in `sixm-server/src/state.rs`, client in `sixm-client/src/host.rs`. M.
2. **State bag natives**: `GetStateBagValue`, `SetStateBagValue`, `StateBagHasKey`, `GetStateBagKeys`, `EnsureEntityStateBag` (name-based access, used by libs that take a bag name from a change handler). Only `Add/RemoveStateBagChangeHandler`, `GetPlayerFromStateBagName`, `GetEntityFromStateBagName` exist. Where: `sixm-lua/src/state.rs`, `sixm-js/src/state.rs`, host trait in `sixm-core`. S.
3. **Database access**: no way to reach MySQL/MariaDB/SQLite. Lua has no sockets, JS has no Node, `PerformHttpRequest` is HTTP only, so `oxmysql` / `mysql-async` / `ghmattimysql` (and every framework on them) cannot run. The `provide` mechanism already lets a built-in resource claim those names. Where: new host API plus crate (e.g. `sixm-sql`), exposed as `exports.oxmysql`-compatible shim resource. L.
4. **`chat` system resource**: `chat:addMessage`, `chat:addTemplate`, `chat:addSuggestion`, `chat:removeSuggestion`, `chat:clear`, `chatMessage` event, `chat:init`, automatic command suggestions. Almost every script calls `TriggerClientEvent('chat:addMessage', ...)`. SixM's example `chat` only listens to `sixm_chat:message` and has a console-only `say`; `chat:*` events from a server are dropped on clients (no handler, `RegisterNetEvent` rule). Server-side contract (events, `chatMessage` cancel, `say`, suggestion registry from `GetRegisteredCommands`) can exist without a UI. Where: `examples/server-data/resources/[system]/chat` (rename from `[examples]`). M.
5. **`spawnmanager` and `mapmanager` contracts**: exports `spawnPlayer`, `addSpawnPoint`, `removeSpawnPoint`, `loadSpawns`, `setAutoSpawn`, `setAutoSpawnCallback`, `forceRespawn`; event `playerSpawned`; mapmanager `addMap/loadMap/unloadMap/parseMap`, events `onClientMapStart`, `onClientGameTypeStart`, `onClientMapStop`, `onClientGameTypeStop`, `getMapDirectives`. Neither is bundled (`docs/guides/from-fivem.md` says so). Scripts that `exports.spawnmanager:...` or wait for `playerSpawned` break at load. The spawn action itself is [game], but the API shape and events are core. Where: `[system]/spawnmanager`, `[system]/mapmanager`. M.
6. **`baseevents` names differ from FiveM**: FiveM emits `baseevents:onPlayerDied`, `onPlayerKilled`, `onPlayerWasted`, `enteringVehicle`, `enteringAborted`, `enteredVehicle`, `leftVehicle`. SixM registers `onPlayerEnteredVehicle`, `onPlayerLeftVehicle`, `onPlayerDied` (`[system]/baseevents/server.lua`), so handlers written for FiveM names never match, and nothing emits them. Where: same file, rename plus add missing channels. S.
7. **`start|stop|restart|ensure <[category]>`**: FiveM accepts a category folder name (`ensure [standard]`, `ensure [local]` are ubiquitous in server.cfg). SixM `resource_command` takes one resource name; `categor` does not occur in `commands.rs` or `manager.rs`. Where: `sixm-server/src/commands.rs` + `sixm-resources/src/catalog.rs` (category to resource list). S.
8. **`server_only 'yes'` manifest key**: no handling anywhere (stored as metadata); client files are still sent. Where: `sixm-resources/src/manifest.rs` plus client file list in `resource_files.rs`. S.
9. **Events missing on server**: `onEntityBucketChange(entity, bucket, oldBucket)`, `onPlayerBucketChange` (core routing-bucket events, `buckets.rs`), `onResourceListRefresh` (after `refresh`), `playerJoining` second arg `oldID`, `playerDropped` extra args `resourceName`, `clientDropReason` (SixM passes only `reason`). Where: `sixm-server/src/buckets.rs`, `manager.rs` (refresh), `network.rs:698,866`. S.
10. **Lua `Citizen.Trace`** and **`PerformHttpRequestAwait`** (old scripts use both; neither string exists in the repo). Where: `sixm-lua/src/natives.rs` (Trace routes to the script log), `http.rs`/`promise.rs`. S.
11. **Lua vector helpers**: `dot`, `cross`, `norm`, `inv`, `slerp`, and the `vector(...)` constructor (listed in the Cfx Lua reference; no matches in `sixm-lua/src/vector.rs`). JS vectors have `.dot/.cross/.normalize`. Where: `sixm-lua/src/vector.rs`. S.
12. **`IsAceAllowed(object)`** (shared native; checks the calling resource's principal). Only `IsPlayerAceAllowed` and `IsPrincipalAceAllowed` exist. Where: `sixm-lua/src/players.rs`, `sixm-js/src/players.rs`, `sixm-server` ACE store. S.
13. **Common info natives** (CFX list, all missing): `GetGameName`, `GetGameBuildNumber`, `GetPlayerGuid`, `GetPlayerTeam`, `GetPlayerTimeOnline`, `GetPlayerFromIndex`, `GetHostId`, `GetInstanceId`, `SetGameType`, `SetMapName` (+ convars `gametype`, `mapname` shown in `/info.json`), `GetResourceCommands`. Where: `sixm-lua/src/natives.rs`, `players.rs`, `resources.rs` and JS twins. S.
14. **JS event aliases**: `addEventListener`, `addNetEventListener`, `addRawEventListener`, `addRawEventHandler`. Only `on`, `onNet`, `removeEventListener`, `AddEventHandler` exist. Raw listeners receive the msgpack payload unparsed. Where: `sixm-js/src/events.rs`. S.
15. **Identifier types**: only `license:` and `ip:`. Scripts probing `steam:`, `discord:`, `fivem:`, `license2:`, `xbl:`, `live:` get nil (see section 5 for the deliberate part). Open question for P1: whether to let `playerConnecting` handlers attach extra identifiers. Left as a decision, not a bug. S.

## 2. P2 - server operators and developer experience

1. **Console commands missing**: `status` (id/name/identifiers/endpoint/ping), `clientkick <id> [reason]`, builtin `say`, `cmdlist`, `seta`, `load_server_icon`. `con_channelFilters`, `con_addChannelFilter`, `con_removeChannelFilter` (log filtering). `exec @resource/file.cfg` (resource-relative exec; no `@` handling in `commands.rs:674`). Where: `sixm-server/src/commands.rs`. S-M.
2. **Per-resource monitor (resmon equivalent)**: `perf` shows frame totals only; the profiler gives per-resource ticks in a trace file. No live per-resource CPU ms and memory table, no `profiler view`, no hitch warnings (`hitch` does not occur in the repo). Lua heap and instruction budgets already exist per runtime, so numbers are available. Where: `sixm-server/src/perf.rs`, `profiler.rs`, `/admin`. M.
3. **Moderation/admin layer (txAdmin-like, self-hosted)**: kick/ban/warn/allowlist store, announcements, scheduled restarts, log viewer, `server.cfg` editor, admin permissions UI. SixM has `/admin` (RCON console + players + resources), `/rcon`, ACE; no ban or allowlist persistence (only the `queue_banned` example convar). `TempBanPlayer` native missing. Where: `sixm-server` (new `moderation.rs`) + `admin.html`. L. Cfx.re-hosted txAdmin pieces (Cfx account login, Cfx portal) are [platform]: skip.
4. **Reverse-proxy awareness**: `sv_proxyIPRanges` (trust `X-Forwarded-For`/`X-Real-IP` from listed CIDRs). Docs already warn that clients behind a proxy share the RCON/HTTP rate limit (`docs/server.md`, Remote console). Where: `sixm-server/src/http.rs`, `web.rs`. S-M.
5. **Metrics auth**: `sv_prometheusBasicAuthUser/Password` (SixM `/metrics` is only on/off). Where: `http.rs`. S.
6. **`deferrals.presentCard` and `deferrals.handover`**: SixM `deferrals` has `defer`, `update`, `done` only (`network.rs:495-497`). `presentCard` (Adaptive Cards for whitelist/ToS flows) needs a card message and callback; `handover` passes data to the loading screen (needs NUI, section 4). Where: `sixm-net` protocol, `network.rs`, client. M.
7. **Lua language extensions (CfxLua)**: SixM `preprocess.rs` implements backtick hashes only. Catalogue lists relative path literals; other Grit-style syntax (compound assignment etc.) is not verified against Cfx docs here. Where: `sixm-lua/src/preprocess.rs`. M.
8. **`SetHttpHandler` request fields**: `req.setCancelHandler` and `req.address` absent (no matches in `sixm-lua/src/web.rs`, `sixm-js/src/web.rs`); handlers that clean up on aborted requests need it. Where: those two files + `sixm-server/src/http.rs`. S.
9. **Entity/world natives with no game dependency**: `GetEntitiesInRadius`, `GetEntityOrphanMode`, `GetNetTypeFromEntity`, `SetEntityIgnoreRequestControlFilter`, `SetPlayerCullingRadius`, `GetEntityRotationVelocity`, `GetEntitySpeed` (exists only in client `--sim`, not in script runtimes). `playerEnteredScope` / `playerLeftScope` events (SixM has scoping in `scope.rs`; catalogue tags them [game], but the data exists in core). Where: `sixm-lua/src/entities.rs`, `sixm-js/src/entities.rs`, `sixm-server/src/scope.rs`. M.
10. **Server-list integration**: `sv_endpointPrivacy`, `sv_lan`, `sv_master1`-style listing, `sets banner_detail`, `sv_projectName/Desc`. SixM has `sv_masterUrl` heartbeat and `/info.json`; no listing service. Self-hosted equivalent: publish heartbeat schema in docs. Where: `docs/server.md`. S.
11. **Docs migration table**: no explicit "FiveM name -> SixM name/absent" table for convars/commands (see section 5). Where: `docs/guides/from-fivem.md`. S.

## 5. Deliberate differences needing notes in `docs/guides/from-fivem.md`

Already documented there: QUIC transport, Lua 5.4 sandbox, shared vectors, `source` kept across `Wait`, headless client, `PlayerId()==0`, ExecuteCommand principal, no client HTTP, no C#.

Not yet documented (add):
1. **Identifiers**: `license:` is the SHA-256 of the client certificate (not Rockstar-verified); no `license2`, `steam`, `discord`, `fivem`, `xbl`, `live`. Tokens are certificate-derived (`GetPlayerToken`). Identity file loss = new player.
2. **No Node.js**: JS is QuickJS ES2023; no `require`, `fs`, `process`, `Buffer`, `setImmediate`, npm, `yarn`/`webpack` resources, `node_version`. Libraries relying on them (oxmysql, many TS bundles) will not load. Verified: `setImmediate`, `TextEncoder`, `structuredClone`, `performance` do not occur in `sixm-js/src`.
3. **Lua sandbox**: `require`, `dofile`, `loadfile`, `io`, most of `os` are nil; `debug` only `traceback`/`getinfo`; `load` accepts text only; 2M-instruction budget per resume and 64 MiB heap (scripts with long synchronous loops get aborted); `__gc` metatables rejected.
4. **Convar permissions**: `GetConvar` of a name restricted with `add_convar_permission` returns the default; console-only convars cannot be set by scripts (`rcon_password`, `sv_httpEnabled`, ...). `SetConvar` limits: 256 B name, 64 KiB value, replicated 4096 B.
5. **Convar names**: `sv_hostname`, `sv_maxclients`, `endpoint_add_*`, `rcon_password` same; `sixm_*` for runtime tunables; `onesync`, `gamename`, `sv_licenseKey`, `sv_scriptHookAllowed`, `sv_enforceGameBuild`, `sv_master1` have no effect (plain convars). `endpoint_add_tcp` sets both ports.
6. **Entity model**: entity id == network id == handle; no orphan/ownership differences between handle spaces; `SetEntityOrphanMode` takes `'delete'|'migrate'` strings; `GetEntityRotation` ignores order; `CreateVehicleServerSetter` ignores type; `sv_entityLockdown` and per-bucket lockdown apply to client creation only; `sixm_cullRadius` default 424 mirrors FiveM.
7. **State bags**: clients cannot write replicated keys (until P1 item 1 lands); `set` is a method name (key `set` unreadable); change handler `reserved` is always 0.
8. **Resource limits**: KVP 64 KiB value / 16 MiB namespace; `SaveResourceFile` 4 MiB and refuses `.lua`/`.js`/manifests; `LoadResourceFile` rejects symlinks/device names; HTTP SSRF guard (`sv_httpAllowPrivate`) and 16 MiB body cap.
9. **Rate limits**: per-player event token bucket (`sv_playerEventRateLimit`, default 60/s, burst 120) and transport flood kick; events over the limit are dropped. Resources with chatty `TriggerServerEvent` loops need batching.
10. **Resource lifecycle**: `GetResourceState` returns `missing` on clients for non-running resources; client `GetResourcePath` only for own resource; client exports must be declared with `export` and sent as lists (max 256).
11. **Server listing and identity**: no Cfx.re server list or auth; clients pin the server fingerprint (`--fingerprint`) instead of a license key.
12. **Admin surface**: RCON is HTTP `POST /rcon` with a bearer password, not the FiveM RCON UDP/`rconCommand` event; `/admin`, `/healthz`, `/metrics` are opt-in.
